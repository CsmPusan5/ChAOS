# Модель вычислительного центра (вариант 45)

Дискретная имитационная модель на C. **Многопоточная версия**: каждая моделируемая сущность с поведением — отдельный pthread-поток; время идёт тиками, которые синхронизируют фазы через семафоры и мьютекс.

## Файлы

| Файл | Назначение |
|------|-----------|
| `sim.h` | типы `Task`, `Node`, `ComputingCenter`, `WorkerArg`, прототипы, `extern` синхропримитивов |
| `main.c` | глобалы, CLI, **точки входа потоков** (`worker_thread`, `clock_thread`), запуск и `pthread_join` |
| `output.c` | вывод в stdout и лог, `delay_ms`, обработчик сигналов |
| `resources.c` | питание, `alloc_take/give/clear`, `power_ok` (с PUE и охлаждением) |
| `placement.c` | размещение на узле/группе, вытеснение |
| `events.c` | **работа фаз** (`node_work`, `task_work`, `scheduler_work`), статус, итоги |
| `config.c` | генерация узлов и заданий |

> Все файлы подхватываются `Makefile` через `wildcard src/*.c` — новые `.c` автоматически попадают в сборку.

## Сущности

- **Node** — узел: ядра/память/мощность (всего и занято), статус `OK/FAILED`, флаг `multi`.
- **Task** — задание: требования, приоритет, дедлайн, флаги `multi/preempt/checkpoint`, состояние, карта размещения (`used_mask` + `alloc_*`).
- **ComputingCenter** — узлы + лимиты `power_limit`, `cooling_limit`, `pue`.

## Модель потоков

| Поток | Сколько | Роль | Что ждёт |
|-------|---------|------|----------|
| `clock_thread` | 1 | «Сердце» модели: двигает `cur_time`, раздаёт фазы | `sem_wait(&ack_sem)` × (N+M+1) |
| `worker_thread` (узел) | `MAX_NODES` (8) | `node_work` — отказ/восстановление | `sem_wait(&node_sem[i])` |
| `worker_thread` (задание) | `MAX_TASKS` (20) | `task_work` — поступление/завершение | `sem_wait(&task_sem[i])` |
| `worker_thread` (планировщик) | 1 | `scheduler_work` — сортировка + раздача ресурсов | `sem_wait(&sched_sem)` |
| `main` | 1 | CLI, старт, `pthread_join`, `print_summary` | — |

Аргумент потока — `WorkerArg { int type; int index; }`:
`type = 1` — узел, `2` — задание, `3` — планировщик. `index` — номер в соответствующем массиве.

## Синхропримитивы (`sim.h` / `main.c`)

| Примитив | Тип | Назначение |
|----------|-----|-----------|
| `mtx` | `pthread_mutex_t` | Защита **всего** разделяемого состояния: `tasks[]`, `center.nodes[]`, счётчиков статистики |
| `node_sem[MAX_NODES]` | `sem_t` | Будит поток узла `i` к очередной фазе |
| `task_sem[MAX_TASKS]` | `sem_t` | Будит поток задания `i` к очередной фазе |
| `sched_sem` | `sem_t` | Будит поток планировщика |
| `ack_sem` | `sem_t` | Квитанция «фаза выполнена» — `clock_thread` ждёт N+M+1 раз, прежде чем перейти к следующей фазе (аналог barrier) |

Инициализация — в `main()` до создания потоков, `sem_destroy`/`pthread_mutex_destroy` — после `pthread_join`.

## Тик (`clock_thread`)

Один тик = **три последовательные фазы**, между которыми `clock_thread` даёт всем рабочим закончить через `ack_sem`:

```
1. ФАЗА УЗЛОВ         → node_work для каждого узла     (отказ / восстановление)
2. ФАЗА ЗАДАНИЙ       → task_work для каждого задания  (поступление / завершение)
3. ФАЗА ПЛАНИРОВЩИКА  → scheduler_work                 (сортировка + размещение + вытеснение)
4. ПОСТ-ФАЗА          → check deadlines, advance(), stat_energy += total_power()
5. status(t) (если verbose) + delay_ms(tick_delay_ms)
```

### Выход

- `Ctrl+C` / `SIGTERM` → `on_signal` ставит `stop_flag = 1`; `clock_thread` завершает тик, будит всех через `sem_post`, все выходят;
- `-t <N>` — по достижении лимита тиков;
- `all_done()` — все задания `DONE` или `FAILED`.

## Планирование (`-s`)

`cmp_jobs` сортирует очередь: **FCFS** (по времени), **PRIO** (по приоритету), **EDF** (по дедлайну, `0` → в конец), **SJF** (по длительности).

## Размещение (`placement.c`)

- **single** — находит узел, где хватает ядер, памяти, мощности.
- **multi** — раскладывает ядра по нескольким узлам, память и мощность пропорционально.
- **preempt** — снимает менее приоритетные задачи и пробует снова; жертва идёт в `PREEMPTED` (с `ckpt` прогресс сохраняется, без — перезапуск).

Проверки: `power_ok` учитывает **PUE** и **лимит охлаждения**.

## Ресурсы (`resources.c`)

Операции по маске `used_mask`: `alloc_take` (занять), `alloc_give` (вернуть), `alloc_clear` (сбросить).

## Генерация (`config.c`)

- Узлы: 2..19 ядер, 2..36 ГБ, 50..199 Вт, 75% `multi`.
- Лимиты: питание = 80% суммы мощностей, охлаждение = 75%, PUE = 1.15.
- Задания: 3..15 тиков, приоритет 1..8, 33% multi, 80% вытесняемые, 67% с чекпоинтом.

## Инварианты

- занятые ресурсы ≤ доступных;
- `Σused · pue ≤ power_limit`, `Σused ≤ cooling_limit`;
- один ресурс — одному заданию;
- завершение/вытеснение освобождает ресурсы;
- результат регистрируется один раз.

## Воспроизводимость

`srand(seed)` вызывается **до** `init_simulation()` и до создания потоков, поэтому **начальная конфигурация** узлов и заданий детерминирована при одинаковом `-n`.

Порядок `rand()` **внутри фаз** недетерминирован из-за параллельного планирования потоков ОС (в `node_work` при отказе узла). Полная побайтовая воспроизводимость между запусками параллельной модели не гарантируется — это её фундаментальное свойство.

## Запуск

```sh
make                         # собрать → build/sim
make rebuild                 # полная пересборка
make run                     # ./build/sim -t 60 -d 150 -n 42
make gen                     # ./build/sim -s edf -t 80
make fail                    # ./build/sim -f 0.05 -t 100
make clean                   # rm -rf build/ log.log
```

Прямой вызов:

```sh
./build/sim -s edf -t 80 -f 0.03 -l run.log
./build/sim -h
```

### Ключи

| Ключ | Значение | По умолчанию |
|------|----------|--------------|
| `-s str` | стратегия: `fcfs` / `prio` / `edf` / `sjf` | `prio` |
| `-t N` | период моделирования (тиков); `0` — без лимита | `60` |
| `-d ms` | задержка между тиками; `0` — без задержки | `150` |
| `-n seed` | зерно генератора | `42` |
| `-l file` | файл лога (дублируется в stdout) | `log.log` |
| `-f p` | вероятность отказа узла за тик, `0..1` | `0.0` |
| `-q` | тихий режим (не печатать статус каждый тик) | — |
| `-h` | справка | — |

## Сборка

`Makefile`:

```make
CC      = gcc
CFLAGS  = -std=c11 -Wall -Wextra -O2 -D_GNU_SOURCE -pthread
LDFLAGS = -pthread

SRC_DIR   = src
BUILD_DIR = build

TARGET  = $(BUILD_DIR)/sim
SRCS    = $(wildcard $(SRC_DIR)/*.c)
OBJS    = $(patsubst $(SRC_DIR)/%.c,$(BUILD_DIR)/%.o,$(SRCS))
DEPS    = $(SRC_DIR)/sim.h
```


## Проверка корректности

```sh
# Сборка без warning'ов
make rebuild 2>&1 | grep -E 'warning|error'    # ожидается пусто

# Завершение по сигналу
timeout -s INT 3 ./build/sim -t 1000 -d 10 -n 1 ; echo "exit=$?"
# Ожидается: "ПРЕРВАНО ПОЛЬЗОВАТЕЛЕМ" в логе, exit=0

# Воспроизводимость начальных условий
./build/sim -t 0 -d 0 -n 42 -q   # конфигурация узлов/заданий одна и та же
```
